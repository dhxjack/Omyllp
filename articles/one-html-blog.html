我用一个 HTML 文件搭了个博客

这个博客的全部代码是 9,455 字节。一个 HTML 文件，一个 CSS 文件，没有框架，没有构建流程，没有 node_modules。

为什么不用框架

我试过静态站点生成器。它们很好，但有个共同点：在写第一篇文章之前，你要先处理配置。主题、插件、版本、构建报错、依赖升级。

而我要的只有四步：打开文件，写，保存，推送。

后来想明白一件事——博客的核心指标不是技术栈的先进程度，而是「从想写到发出去」的距离。距离越长，写的东西越少。工具应该降低摩擦，而不是制造摩擦。

对比项静态站点生成器单文件 HTML
上手成本中，要装工具链低，记事本即可
加一篇文章写 Markdown + 构建复制一个 HTML 改内容
可扩展性强，标签、归档、搜索现成弱，都要手工做
依赖Node / Go 运行时无

一个文件能装下什么

现在这个站的结构很简单：首屏标语、三个板块卡片、页脚。样式抽成一份独立的 CSS，全站共用——这样以后改配色，只改一个文件。

没有外部字体，没有 CDN，没有图片依赖。整个站点 15 KB 左右，首屏加载不到 0.3 秒。

代价也很清楚：

  • 加文章要手工改 HTML；
  • 没有标签、搜索、归档；
  • 没有评论区。

这些在只有几篇、十几篇的时候，都不是真问题。等它成为真问题再解决也不迟——那时你手上已经有内容了，而内容恰恰是最难的那部分。

部署链路

拆开看只有三件事：代码放哪、谁托管、HTTPS 从哪来。

代码放在 GitHub 的公开仓库，一个 main 分支，没有其他分支。

托管用帽子云，国内的静态托管平台，静态站免费。连上 GitHub 后，推送即自动构建。构建命令和输出目录都留空——纯 HTML 没有构建步骤，留空反而最稳。

域名用自己的，解析托管在 Cloudflare。加一条 CNAME，指向平台给的地址即可。

这里有个关键细节：CNAME 的记录必须设为 DNS only（灰色云）。橙色云状态下流量会走 Cloudflare 代理，平台那边验证不到真实记录，证书签发直接失败。

证书在平台内申请，Let's Encrypt，HTTP 验证，90 天有效期，到期前自动续签。签发完成后，http 访问会自动 301 跳到 https，HSTS 也已开启。

习惯命令行的人，发布就是三行：

git add .
git commit -m "post: 新增一篇文章"
git push

我用的是网页上传，效果一样，只是少了装 Git 这一步。

踩过的三个坑

第一，记录加错了地方。域名的 NS 指向 Cloudflare，我却在阿里云云解析里加 CNAME。页面上明明有一条黄色警告写着「当前配置的解析记录不会生效」，我没细看，白等了半小时。

第二，终端被日志刷屏。敲一个 nslookup，满屏 HTTP timeout 警告，一度以为命令敲错了。其实是 mise 在后台检查工具版本，跟命令本身毫无关系。

第三，把「能打开」当成了「已备案」。域名指向境外节点时，未备案也能正常访问；只有指向国内节点，备案才是硬门槛。这两件事没有因果关系，很容易被误导。

这和自由有什么关系

这个博客有三个板块：法律、LINUX、哲学。看着不搭，其实是一条线——自由的三种形态。

  • 法律是自由的外部边界：谁划定、划到哪、越界之后怎么办；
  • 哲学是自由的内在根据：为什么要自由、自由是否可能；
  • LINUX 是自由的技术实践：代码可读、可改、可分发。

一个静态博客恰好是第三种的最小样本：文件在你手里，托管随时能换，平台倒了内容还在，改一行字只需要一个文本编辑器。

这不是技术选择，是所有权问题。
